# TriCoder 第一轮能力完善设计

## 目标

把现有“能够演示工具循环”的 MVP 提升为“能够可靠完成小型真实编码任务”的版本，同时保持工作区隔离、人工审批、凭据保护和中文可读性。

## 功能边界

### 创建文件

- 新增 `create_file` 工具，参数为 `path` 和 `content`。
- 只允许在工作区内创建 UTF-8 文本文件。
- 敏感路径、目录穿越和符号链接逃逸继续由 `WorkspacePolicy` 拦截。
- 父目录必须已经存在，首版不隐式创建目录。
- 目标文件已存在时拒绝覆盖。
- 写入前展示从空文件到完整内容的统一 Diff，并要求人工批准。
- 审批前绑定父目录身份，审批后重新解析目标并核对父目录身份；POSIX 使用目录句柄相对发布，Windows 使用防重命名目录句柄锁，无法安全绑定时拒绝写入。
- 先写完整的同目录临时文件，再用 `os.link` 原子发布；目标已存在或文件系统不支持硬链接时安全失败，绝不降级覆盖。硬链接成功后即视为已提交，临时链接清理失败只返回清理警告。

### 完成与验证状态

- Agent 跟踪 `未运行`、`待验证`、`通过`、`失败` 四种公开验证状态。
- `create_file` 或 `edit_file` 成功后状态变为 `待验证`。
- 随后的 `run_command` 成功时变为 `通过`，失败时变为 `失败`。
- 模型调用 `finish` 后结束循环。
- 没有文件修改的分析任务可以成功完成。
- 有文件修改时，仅当最新修改之后存在一次成功验证，`RunResult.ok` 才为真；否则返回未完全成功和非零退出码，但保留已经批准的修改。

### 审计目录

- 审计日志默认写到操作系统本地状态目录，不在目标工作区创建 `runtime/`。
- Windows 默认使用 `%LOCALAPPDATA%\TriCoder\runs`。
- 其他平台优先使用 `$XDG_STATE_HOME/tricoder/runs`，否则使用用户目录下的 `.local/state/tricoder/runs`。
- 新增 `--audit-dir` 显式覆盖默认目录。
- 审计记录只保存结构化脱敏元数据；理由改记字符数，命令改记程序、允许模块或 Git 子命令及参数数量，不保存源码正文、完整命令或 API Key。
- CLI 在创建 Provider 前预检审计文件可追加；运行期间追加失败时安全停止并返回失败。
- `--read-only` 对目标工作区保持零写入。

### 上下文预算

- `AppConfig` 新增 `max_context_chars`，默认 `80_000`，可由 `.tricoder.toml` 的 `[agent]`、环境变量 `TRICODER_MAX_CONTEXT_CHARS` 和 CLI `--max-context-chars` 覆盖。
- 在每次模型请求前压缩消息历史。
- system prompt 和原始用户任务永远保留。
- 后续消息按完整的 `assistant` 动作与 `user` 工具结果组成回合，从新到旧保留，再恢复原顺序；超预算时不保留半个回合。
- 发生淘汰时，在原始任务之后插入一条固定说明，告知模型早期交互已省略、必要时重新读取文件。
- 若固定消息本身已超过预算，仍保留固定消息，避免截断系统指令或用户任务。

## 测试要求

- 每项行为先增加失败测试，再写最小实现。
- 测试不得读取真实 `.env.local`，不得发起网络请求。
- 创建文件测试必须覆盖成功、拒绝审批、文件已存在和敏感路径。
- 完成判定必须覆盖无修改、修改未验证、验证失败、修改后验证成功以及验证后再次修改。
- 审计目录必须覆盖默认路径、CLI 覆盖和目标工作区零写入。
- 上下文预算必须覆盖不超限、淘汰最旧消息、保留固定消息和配置优先级。

## 非目标

- 本轮不实现文件删除、移动、目录创建、任意 Shell 命令或依赖安装。
- 本轮不实现模型原生 tool calling、tokenizer、流式输出或交互式会话。
- 本轮不初始化 Git、不提交、不发布。
